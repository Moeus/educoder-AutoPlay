# 面向 Educoder 的视频进度抓取脚本

基于 [DrissionPage](https://github.com/g1879/DrissionPage) 实现的 Educoder 视频页面自动化辅助脚本。

脚本通过浏览器自动化获取 Educoder 视频列表及播放进度，自动识别未完成的视频，依次打开视频播放页面并监听当前播放时间与视频总时长。当检测到当前视频播放结束后，会自动关闭当前视频页面并切换到下一个待处理视频。

支持启动多个相互隔离的 Chromium 实例，可分别登录不同账号，各实例之间的 Cookie、登录状态和浏览器数据互不影响。

## 功能

* 自动启动独立 Chromium 浏览器实例
* 支持 Educoder 账号手动登录
* 自动获取视频列表
* 自动读取视频完成进度
* 自动跳过进度为 `100%` 的视频
* 自动打开未完成的视频
* 自动点击播放器播放按钮
* 自动监听当前播放时间
* 自动获取视频总时长
* 视频结束后自动关闭播放页面
* 自动切换到下一个视频
* 支持多个浏览器实例同时运行
* 支持多个账号分别登录
* 每个实例使用独立浏览器环境
* 程序结束或出现异常时自动清理浏览器数据
* 自动清理 Cookie、LocalStorage、SessionStorage 和浏览器缓存
* 自动关闭 Chromium 实例

## 工作流程

脚本启动后的基本流程如下：

```text
启动 Chromium
       │
       ▼
打开 Educoder
       │
       ▼
用户手动登录账号
       │
       ▼
用户进入视频列表页面
       │
       ▼
按回车开始执行
       │
       ▼
扫描所有视频卡片
       │
       ├── 进度 = 100%
       │       └── 跳过
       │
       └── 进度 != 100%
               │
               ▼
          加入待处理队列
               │
               ▼
          打开视频页面
               │
               ▼
          点击播放按钮
               │
               ▼
      监听当前时间 / 总时长
               │
               ▼
       当前时间 >= 总时长
               │
               ▼
          视频播放结束
               │
               ▼
        关闭当前视频 Tab
               │
               ▼
           下一个视频
```

## 环境要求

需要本机能够正常运行 Chromium / Chrome 类浏览器。

项目使用 Python 和 DrissionPage。

如果使用 `uv`，项目已经配置好 `pyproject.toml`，可以直接使用项目环境。

如果直接使用 Python，则需要自行安装相关依赖。

---

## 使用 uv 启动

推荐使用 `uv`。

首先同步项目环境：

```bash
uv sync
```

然后启动脚本：

```bash
uv run python main.py
```

如果项目已经在 `pyproject.toml` 中配置了对应的启动入口，也可以直接：

```bash
uv run <项目入口名称>
```

实际入口名称以项目中的 `pyproject.toml` 配置为准。

---

## 使用 Python 启动

如果不使用 `uv`，需要先准备 Python 环境并安装依赖。

安装 DrissionPage：

```bash
pip install -U DrissionPage
```

然后运行：

```bash
python main.py
```

Windows 环境下也可以使用：

```bash
py main.py
```

如果你的脚本文件不是 `main.py`，请将命令中的文件名替换为实际文件名。

## 使用方法

启动程序：

```bash
uv run python main.py
```

或者：

```bash
python main.py
```

浏览器启动后，程序会自动打开：

```text
https://www.educoder.net/
```

随后按照终端提示操作：

```text
1. 登录头歌实践教学平台
2. 进入需要处理的课程
3. 打开对应的视频列表页面
4. 保持视频列表页面处于打开状态
5. 回到终端按回车
```

程序随后会扫描当前页面的视频列表。

例如：

```text
正在扫描视频列表...

共发现 8 个视频卡片。

[1] 第一章课程介绍 进度：100%
    -> 已完成，跳过

[2] Python 基础 进度：42%

[3] 数据结构介绍 进度：100%
    -> 已完成，跳过

[4] 算法基础 进度：13%

扫描完成，需要播放 2 个视频。
```

之后程序会按照队列顺序依次处理未完成的视频。

播放过程中终端会实时显示：

```text
[播放] 03:21 / 07:34
```

视频结束后：

```text
视频播放结束。
关闭当前视频标签页...
返回视频列表。
```

然后自动进入下一个视频。

## 多实例 / 多账号

项目支持同时启动多个独立的浏览器实例。

程序使用 DrissionPage 的独立 Chromium 配置：

```python
options = ChromiumOptions().auto_port()
browser = Chromium(options)
```

`auto_port()` 会为当前实例分配独立的调试端口和临时用户数据目录。

因此不同进程之间的：

```text
Cookie
登录状态
LocalStorage
SessionStorage
缓存
浏览器用户数据
```

不会互相共用。

如果需要运行多个实例，可以分别打开多个终端。

例如终端 1：

```bash
uv run python main.py
```

终端 2：

```bash
uv run python main.py
```

终端 3：

```bash
uv run python main.py
```

也可以使用普通 Python：

```bash
python main.py
```

在不同终端中分别启动。

每个程序都会创建自己的 Chromium 实例，因此可以在各自的浏览器中分别登录不同账号。

例如：

```text
进程 1
└── Chromium A
    └── 账号 A

进程 2
└── Chromium B
    └── 账号 B

进程 3
└── Chromium C
    └── 账号 C
```

各实例互不共享登录状态。

实际可同时运行多少实例取决于电脑的：

* CPU
* 内存
* 网络带宽
* Chromium 资源占用

视频页面本身通常会占用较多内存，因此不建议一次启动超过机器能够稳定承受的实例数量。

## 浏览器数据清理

程序结束时会执行浏览器清理逻辑。

无论是：

* 正常执行完成
* 播放过程中发生异常
* 用户使用 `Ctrl+C` 中止程序

都会进入最终清理流程。

清理内容包括：

```text
SessionStorage
LocalStorage
Cookie
浏览器 Cache
Chromium 临时用户数据目录
```

最后关闭 Chromium。

主要流程：

```text
程序结束 / 出现异常
        │
        ▼
获取所有 Tab
        │
        ▼
清理 SessionStorage
        │
        ▼
清理 LocalStorage
        │
        ▼
清理 Cookie
        │
        ▼
清理 Cache
        │
        ▼
关闭 Chromium
        │
        ▼
删除临时用户数据目录
```

这样下一次启动程序时会获得新的浏览器环境，不会自动继承上一次运行时的登录账号。

---

## 强制停止

运行过程中可以通过：

```text
Ctrl + C
```

停止程序。

程序捕获 `KeyboardInterrupt` 后会进入清理流程，并尝试：

1. 清除当前浏览器中的网站数据
2. 清除 Cookie 和缓存
3. 关闭 Chromium
4. 删除临时浏览器用户数据

不建议直接使用任务管理器强制结束 Python 或 Chromium 进程，因为这种方式可能导致程序无法执行正常的退出清理逻辑。

## 配置项

主要配置集中在脚本顶部。

例如：

```python
EDUCODER_URL = 'https://www.educoder.net/'

CHECK_INTERVAL = 3

PLAYER_LOAD_WAIT = 3

AFTER_VIDEO_WAIT = 3
```

### `CHECK_INTERVAL`

视频播放过程中多久检查一次时间。

默认：

```python
CHECK_INTERVAL = 3
```

表示每 3 秒检查一次。

### `PLAYER_LOAD_WAIT`

视频页面打开后等待播放器初始化的时间。

默认：

```python
PLAYER_LOAD_WAIT = 3
```

### `AFTER_VIDEO_WAIT`

视频结束后等待页面处理进度的时间。

默认：

```python
AFTER_VIDEO_WAIT = 3
```

## 注意事项

本项目依赖 Educoder 当前网页 DOM 结构。

如果 Educoder 更新：

* 视频卡片结构
* 进度条结构
* 视频播放器
* 播放按钮 ID
* 时间显示元素

脚本中的 CSS Selector 可能需要同步修改。

目前主要依赖以下选择器：

```python
CARD_SELECTOR = 'css:.ant-card-body'

PROGRESS_SELECTOR = 'css:.ant-progress-text'

PLAY_SELECTOR = 'css:#play'

VIDEO_CURRENT_SELECTOR = 'css:#time-elapsed'

VIDEO_DURATION_SELECTOR = 'css:#duration'
```

建议在出现定位问题时首先使用浏览器开发者工具检查这些 DOM 元素是否仍然存在。
